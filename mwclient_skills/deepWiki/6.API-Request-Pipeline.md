## Purpose and Scope

This page documents the internal call stack that every API request passes through in mwclient, from the public `site.get()` / `site.post()` methods down to the raw HTTP layer. It covers parameter injection at each layer, how the JSON response is validated, which error conditions trigger a retry versus an exception, and how `raw_index` targets `index.php` instead of `api.php`.

For the retry/back-off mechanism itself (the `Sleeper` / `Sleepers` classes), see [Retry Mechanism and Rate Limiting](/mwclient/mwclient/2.4-retry-mechanism-and-rate-limiting). For authentication details (login, OAuth, token caching), see [Authentication](/mwclient/mwclient/2.2-authentication).

## Layer-by-Layer Reference

### site.get() and site.post()

[mwclient/client.py L333-L369](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L333-L369)

Both are one-line wrappers that call `api()` with a fixed `http_method`.

| Method | `http_method` passed to `api()` |
| --- | --- |
| `site.get(action, **kwargs)` | `'GET'` |
| `site.post(action, **kwargs)` | `'POST'` |

Neither method adds any parameters of its own.

---

### site.api()

[mwclient/client.py L371-L431](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L371-L431)

This is the main public interface. It performs the following transformations and then runs a retry loop.

**Parameter injection for `action='query'`**

| Injected parameter | Value | Purpose |
| --- | --- | --- |
| `continue` | `''` | Enables new-style continuation (MW 1.21–1.25 compatibility) |
| `meta` | `...\|userinfo` appended | Pulls user state on every query |
| `uiprop` | `...\|blockinfo\|hasmsg` appended | Gets block status and message flags |

**Retry loop**

```
sleeper = self.sleepers.make()
while True:
    info = self.raw_api(action, http_method, **kwargs)
    if self.handle_api_result(info, sleeper=sleeper):
        return info
```

The loop exits when `handle_api_result` returns `True`. It retries when `handle_api_result` returns `False` (after calling `sleeper.sleep()` internally). Fatal errors cause `handle_api_result` to raise rather than return.

Sources: [mwclient/client.py L408-L431](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L408-L431)

### site.handle_api_result()

[mwclient/client.py L433-L496](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L433-L496)

Called after every `raw_api` response. Handles three categories of outcome:

**Side-effect updates (always applied)**

| Attribute | Updated from |
| --- | --- |
| `self.blocked` | `info['query']['userinfo']['blockedby']` |
| `self.hasmsg` | presence of `'messages'` in userinfo |
| `self.logged_in` | absence of `'anon'` in userinfo |

Any `warnings` in the response are forwarded to the Python `logging` subsystem at `WARNING` level.

**Retriable error codes (returns `False` after sleeping)**

| Error code | Reason |
| --- | --- |
| `internal_api_error_DBConnectionError` | Transient database connection failure |
| `internal_api_error_DBQueryError` | Transient database query failure |
| `mwoauth-invalid-authorization` with `"Nonce already used"` | OAuth nonce collision ([phabricator T106066](https://phabricator.wikimedia.org/T106066)) |

**Fatal errors (raises `errors.APIError`)**

* If `info['error']['query']` is present (Semantic MediaWiki format): `APIError(None, info['error']['query'], kwargs)`
* If `info['error']['*']` is present: `APIError(code, info, extended_info)`
* Otherwise: `APIError(code, info, kwargs)`

Sources: [mwclient/client.py L433-L496](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L433-L496)

### site.raw_api()

[mwclient/client.py L623-L668](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L623-L668)

The bridge between the high-level parameter dict and the HTTP transport. It:

1. Adds `action=<action>` and `format='json'` to `kwargs`.
2. Calls `_query_string()` to produce an `OrderedDict` that places `wpEditToken` and `token` keys **last** (to avoid truncation in some server-side log formats).
3. Calls `raw_call('api', data, retry_on_error=retry_on_error, http_method=http_method)`.
4. JSON-decodes the raw text using `json.loads(..., object_pairs_hook=OrderedDict)`.
5. On decode failure: raises `errors.APIDisabledError` if the response starts with `"MediaWiki API is not enabled"`, otherwise raises `errors.InvalidResponse`.

**`_query_string()` ordering**

[mwclient/client.py L498-L507](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L498-L507)

```
non_token_params + token_params
```

Token keys (`wpEditToken`, `token`) are always appended after all other parameters.

Sources: [mwclient/client.py L498-L507](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L498-L507)

 [mwclient/client.py L623-L668](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L623-L668)

### site.raw_call()

[mwclient/client.py L509-L621](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L509-L621)

The lowest-level method. Constructs the URL and manages the transport-level retry loop.

**URL construction**

```
{scheme}://{host}{self.path}{script}{self.ext}
```

For `raw_api` calls, `script='api'` → resolves to e.g. `https://en.wikipedia.org/w/api.php`.  

For `raw_index` calls, `script='index'` → resolves to e.g. `https://en.wikipedia.org/w/index.php`.

**HTTP method dispatch**

| `http_method` | Data placement |
| --- | --- |
| `'GET'` | Parameters sent as `params=` (query string) |
| `'POST'` | Parameters sent as `data=` (request body, form-encoded) |

**Transport retry conditions**

```

```

Key behaviors:

* **HTTP 4xx** (except 429): raises `requests.exceptions.HTTPError` immediately, no retry.
* **HTTP 5xx or 429**: retried up to `max_retries` times with exponential back-off via `Sleeper`.
* **`x-database-lag` header**: the value of the `retry-after` header is passed as `min_time` to `sleeper.sleep()`, so the wait is at least as long as the server requests.
* **`ConnectionError` / `Timeout`**: retried if `retry_on_error=True` (the default).
* **`retry_on_error=False`**: skips all transport retries; the caller is responsible for handling exceptions.

Sources: [mwclient/client.py L509-L621](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L509-L621)

### site.raw_index()

[mwclient/client.py L670-L703](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L670-L703)

Targets `index.php` rather than `api.php`. Used for operations that are not available through the JSON API (e.g., certain legacy forms of page editing).

**Differences from `raw_api`**

| Aspect | `raw_api` | `raw_index` |
| --- | --- | --- |
| Target script | `api` (`api.php`) | `index` (`index.php`) |
| Adds `format=json` | Yes | No |
| Adds `maxlag=` | No | Yes (`self.max_lag`) |
| Return value | Parsed `dict` | Raw `str` |
| JSON error handling | Yes | No |

`raw_index` always injects `maxlag=self.max_lag` to respect server-side lag limits. The caller receives the raw response text and must parse it.

Sources: [mwclient/client.py L670-L703](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L670-L703)

## Two Distinct Retry Loops

There are two independent retry loops operating at different levels of the stack. They share the same `Sleepers` factory but create separate `Sleeper` instances.

| Loop location | Method | Triggers | Sleeper created by |
| --- | --- | --- | --- |
| Transport level | `raw_call()` | 5xx, 429, DB-lag header, `ConnectionError`, `Timeout` | `self.sleepers.make((script, data))` |
| Application level | `api()` via `handle_api_result()` | `DBConnectionError`, `DBQueryError`, nonce-reuse | `self.sleepers.make()` |

Both loops raise `errors.MaximumRetriesExceeded` once their respective `Sleeper` exhausts `max_retries`.

The `retry_on_error=False` parameter (accepted by `raw_call` and `raw_api`) disables **only** the transport-level retry. The application-level retry in `api()` is always active unless `raw_api` is called directly.

## self.connection and Session Configuration

All HTTP requests pass through `self.connection`, which is a `requests.Session` instance. It carries:

* **Auth**: `OAuth1` object, `HTTPBasicAuth`, or `None` — set at `Site.__init__` time ([mwclient/client.py L146-L160](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L146-L160) )
* **Cert**: client certificate, set via `self.connection.cert` ([mwclient/client.py L178-L179](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L178-L179) )
* **Headers**: `User-Agent` (mwclient default plus optional `clients_useragent` prefix), plus any `custom_headers` ([mwclient/client.py L181-L189](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L181-L189) )
* **Per-request options**: `self.requests` dict (`connection_options` parameter), merged into every call in `raw_call` ([mwclient/client.py L567-L573](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L567-L573) ). Defaults to `{'timeout': 30}` if not otherwise specified.

A pre-built session can be injected via the `pool` constructor parameter, in which case all of the above session configuration is skipped.

Sources: [mwclient/client.py L92-L191](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L92-L191)
