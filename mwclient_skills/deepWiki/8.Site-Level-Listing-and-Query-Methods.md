## Purpose and Scope

This page documents the methods and attributes on the `Site` class ([mwclient/client.py](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py)

) that enumerate wiki content or query the MediaWiki API for structured results. This includes lazy-iterator listing methods, direct content query methods, action methods, and the Semantic MediaWiki extension interface.

For the underlying pagination and lazy-iteration mechanism shared by all `List`-based returns, see [Iteration and Pagination](/mwclient/mwclient/5-iteration-and-pagination). For authentication required before calling write-capable methods, see [Authentication](/mwclient/mwclient/2.2-authentication). For how API calls are dispatched and retried, see [API Request Pipeline](/mwclient/mwclient/2.3-api-request-pipeline).

## Common Return Types

Most listing methods return a subclass of `List` from `mwclient/listing.py`. These are **lazy iterators**: no API call is made until items are consumed. Chunks are fetched on demand and continuation tokens are followed automatically.

| Return Type | Defined In | What It Yields |
| --- | --- | --- |
| `List` | [mwclient/listing.py L11-L64](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L11-L64) | Raw API response dicts |
| `NestedList` | [mwclient/listing.py L161-L167](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L161-L167) | Raw dicts from a nested response field |
| `GeneratorList` | [mwclient/listing.py L170-L213](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L170-L213) | `Page`, `Image`, or `Category` objects |
| `PageList` | [mwclient/listing.py L266-L352](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L266-L352) | `Page`, `Image`, or `Category` (via `allpages` generator) |
| `list[dict]` | — | Plain Python list; returned by `revisions()` |
| `str` or `tuple` | — | Returned by `expandtemplates()` |
| `dict` | — | Returned by `parse()`, `patrol()` |
| `generator` | — | Returned by `ask()` (Semantic MediaWiki) |

The maximum number of items requested per API call defaults to `Site.api_limit = 500` ([mwclient/client.py L90](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L90-L90)

). Pass `api_chunk_size` or `max_items` to `List.__init__` to override this ([mwclient/listing.py L47-L54](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L47-L54)

).

## Site Namespace Iterators

Three `PageList` attributes are set up on every `Site` instance at construction time:

```
site.pages       → PageList(site, namespace=0)
site.categories  → PageList(site, namespace=14)
site.images      → PageList(site, namespace=6)
```

[mwclient/client.py L193-L201](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L193-L201)

These are `PageList` objects ([mwclient/listing.py L266-L352](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L266-L352)

), which subclass `GeneratorList`. They support both subscript access and iteration:

| Usage | Behaviour |
| --- | --- |
| `site.pages['Article Name']` | Returns a `Page`, `Image`, or `Category` object (no API call yet) |
| `site.pages.get('Article Name')` | Same as subscript |
| `for page in site.pages` | Iterates all pages in namespace 0 via `allpages` API list |
| `for cat in site.categories` | Iterates all pages in namespace 14 |
| `for img in site.images` | Iterates all pages in namespace 6 |

`PageList.get()` dispatches to the correct subclass based on namespace ([mwclient/listing.py L295-L332](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L295-L332)

):

* namespace 6 → `mwclient.image.Image`
* namespace 14 → `listing.Category`
* all others → `mwclient.page.Page`

`PageList.guess_namespace()` infers the namespace from the page name prefix when namespace is 0 ([mwclient/listing.py L334-L352](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L334-L352)

).

`site.Pages`, `site.Categories`, `site.Images` are compatibility aliases pointing to the same objects ([mwclient/client.py L199-L201](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L199-L201)

).

## Full Method Reference

### All-* Enumeration Methods

These methods enumerate all entries of a given type across the wiki. They use the `allpages`, `allimages`, `alllinks`, `allcategories`, and `allusers` MediaWiki API list operations.

| Method | API `list=` | Prefix | Supports `generator=True` | Yields |
| --- | --- | --- | --- | --- |
| `allpages(start, prefix, namespace, redirects, end, limit, ...)` | `allpages` | `ap` | Yes | `Page` objects (generator) or raw dicts |
| `allimages(start, prefix, minsize, maxsize, limit, ...)` | `allimages` | `ai` | Yes | `Image` objects (generator) or raw dicts |
| `alllinks(start, prefix, unique, prop, namespace, limit, ...)` | `alllinks` | `al` | Yes | raw dicts |
| `allcategories(start, prefix, dir, limit, ...)` | `allcategories` | `ac` | Yes | raw dicts |
| `allusers(start, prefix, groups, prop, limit, ...)` | `allusers` | `au` | No | raw dicts |

When `generator=True` is passed (where supported), the method constructs a `GeneratorList` instead of a `List`, switching from `list=allpages` to `generator=allpages` and augmenting the response with full page metadata via `prop=info|imageinfo`. This allows the iterator to yield fully-populated `Page`, `Image`, or `Category` objects.

The distinction between `generator=True` and `generator=False` is provided by `List.get_list()` ([mwclient/listing.py L156-L158](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L156-L158)

) and `List.get_prefix()` ([mwclient/listing.py L153-L154](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L153-L154)

).

### Activity and Log Methods

| Method | API `list=` | Prefix | Key Parameters |
| --- | --- | --- | --- |
| `recentchanges(start, end, dir, namespace, prop, show, limit, ...)` | `recentchanges` | `rc` | `start`/`end` are ISO timestamps; `show` filters flags |
| `logevents(type, user, title, start, end, dir, limit, ...)` | `logevents` | `le` | `type` = one of `block`, `delete`, `move`, `patrol`, etc. |
| `blocks(start, end, users, ip, limit, ...)` | `blocks` | `bk` | `users` filters to specific usernames |
| `deletedrevisions(start, end, user, namespace, limit, ...)` | `deletedrevisions` | `drv` | Requires `deletedhistory` right |
| `exturlusage(query, prop, protocol, namespace, limit, ...)` | `exturlusage` | `eu` | `query` is a URL pattern |
| `usercontributions(user, start, end, dir, namespace, prop, show, limit, ...)` | `usercontributions` | `uc` | `user` is a username string |
| `random(namespace, redirect, limit, ...)` | `random` | `rn` | `namespace` filters by namespace ID |
| `checkuserlog(user, ip, limit, ...)` | `checkuserlog` | `cul` | Requires CheckUser extension; returns `NestedList` |

All of these return a `List` instance unless noted. Items yielded are raw API response dicts. `timestamp` fields are automatically converted to `time.struct_time` by `List.__next__()` ([mwclient/listing.py L87-L88](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L87-L88)

).

### Search

```
site.search(search, namespace='', what='text', redirects=False, limit=None)
```

Uses `list=search` (prefix `sr`). Returns a `List` yielding raw search result dicts. Each dict contains at minimum `title`, `ns`, and `pageid`. The `what` parameter controls the search backend (`text` for full-text, `title` for title search).

---

### Users

```
site.users(users, prop='groups|editcount')
```

Uses `list=users` (prefix `us`). `users` is a list of usernames. Returns a `List` of user info dicts. Unlike `allusers`, this targets specific named users rather than enumerating all users.

Looks up specific revisions by their revision ID. `revids` is a list of integer revision IDs; the method joins them as a pipe-separated string for the API call.

### Content Methods

#### expandtemplates(text, title=None, generatexml=False)

Calls `action=expandtemplates`. Expands MediaWiki template syntax in `text` and returns the resulting wikitext.

Return value depends on `generatexml` and the MediaWiki version:

| MW Version | `generatexml=False` | `generatexml=True` |
| --- | --- | --- |
| < 1.24 | `str` from `expandtemplates['*']` | `tuple(str, str)`: wikitext + `parsetree['*']` |
| ≥ 1.24 | `str` from `expandtemplates['wikitext']` | `tuple(str, str)`: wikitext + `expandtemplates['parsetree']` |

In both cases, when `generatexml=True`, the returned tuple is `(expanded_wikitext, parse_tree_xml)`.

Sources: [test/test_client.py L1007-L1073](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L1007-L1073)

 [test/integration.py L114-L123](https://github.com/mwclient/mwclient/blob/47ea5b29/test/integration.py#L114-L123)

#### parse(text, title=None, ...)

Calls `action=parse`. Returns the raw API response dict containing the parsed HTML, sections, links, and other metadata as returned by MediaWiki. Unlike `expandtemplates`, this returns the full structured parse result rather than a single string.

### Action Methods

#### patrol(rcid=None, revid=None)

Calls `action=patrol` to mark a recent change as patrolled.

* On MediaWiki ≥ 1.17: acquires a `patrol` token via `get_token('patrol')`
* On MediaWiki < 1.17: acquires an `edit` token via `get_token('edit')`

Returns the `dict` at `response['patrol']`, which contains `rcid`, `ns`, and `title`.

### Semantic MediaWiki Extension: ask(query, title=None)

```

```

Calls `action=ask` from the [Semantic MediaWiki](https://www.semantic-mediawiki.org/) extension. The `query` string follows SMW inline query syntax.

Returns a **generator** of result dicts. The method handles both SMW response format versions:

| SMW Version | `query.results` shape | Iteration |
| --- | --- | --- |
| ≤ 0.5 | `list` | Iterates directly |
| ≥ 2 | `dict` (keyed by page title) | Iterates `.values()` |

Each yielded dict typically contains:

| Field | Description |
| --- | --- |
| `fulltext` | Page title as displayed |
| `fullurl` | Full URL of the page |
| `namespace` | Namespace ID |
| `printouts` | Dict of requested property values |
| `exists` | Whether the page exists |

If the SMW API returns an error, `handle_api_result` raises `errors.APIError` with `code=None` (since SMW uses a non-standard `error.query` format instead of `error.code`/`error.info`) ([mwclient/client.py L487-L489](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L487-L489)

).

## Parameter Patterns Across Listing Methods

Most listing methods follow consistent parameter naming conventions inherited from the MediaWiki API prefix system. The `List.generate_kwargs()` static method ([mwclient/listing.py L143-L150](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L143-L150)

) converts these into prefixed API parameters by skipping `None` and `False` values.

| Parameter (unprefixed) | Prefixed form | Type | Meaning |
| --- | --- | --- | --- |
| `start` | `{prefix}start` | ISO timestamp or string | Start of range |
| `end` | `{prefix}end` | ISO timestamp or string | End of range |
| `dir` | `{prefix}dir` | `'newer'` or `'older'` | Sort direction |
| `namespace` | `{prefix}namespace` | `int` | Namespace filter |
| `limit` | `{prefix}limit` | `int` | Chunk size (deprecated alias for `api_chunk_size`) |
| `api_chunk_size` | `{prefix}limit` | `int` | Items per API request (max `Site.api_limit = 500`) |
| `max_items` | — | `int` | Total items to yield before stopping |

For generator-mode calls, the prefix is prepended with `g` (e.g., `gaplimit` instead of `aplimit`). This is handled by `List.get_prefix(prefix, generator=True)` ([mwclient/listing.py L153-L154](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/listing.py#L153-L154)

).
