This page documents every exception class defined in `mwclient/errors.py`, what condition triggers each one, and which layer of the stack raises it. It also covers the `TYPE_CHECKING` import pattern used to avoid circular imports.

For information on the retry mechanism that raises `MaximumRetriesExceeded`, see the [Retry Mechanism and Rate Limiting](/mwclient/mwclient/2.4-retry-mechanism-and-rate-limiting) page. For authentication-related flows that raise `LoginError`, see [Authentication](/mwclient/mwclient/2.2-authentication).

---

## Overview

All mwclient-specific exceptions inherit from `MwClientError`, which itself extends Python's built-in `RuntimeError`. This means callers can catch all mwclient errors with a single `except MwClientError` clause, or catch specific subclasses for fine-grained handling.

The exceptions fall into five functional groups:

| Group | Base Class | Covers |
| --- | --- | --- |
| Connection / compatibility | `MwClientError` | `MediaWikiVersionError`, `APIDisabledError`, `InvalidResponse` |
| API-level errors | `APIError` | Any error object returned in the API JSON response |
| Permission errors | `InsufficientPermission` | Blocked users, protected pages, missing upload rights |
| Edit errors | `EditError` | Failed edits, captcha, file conflicts |
| Authentication errors | `LoginError` | Login failure, OAuth rejection |

## Exception Reference

### MwClientError

[mwclient/errors.py L7-L9](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L7-L9)

Base class for the entire hierarchy. Extends `RuntimeError`. Catching `MwClientError` catches all library-specific errors.

---

### APIError

[mwclient/errors.py L27-L39](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L27-L39)

Raised by `handle_api_result()` in `client.py` when the MediaWiki API response JSON contains a top-level `"error"` key.

**Attributes:**

| Attribute | Type | Description |
| --- | --- | --- |
| `code` | `Optional[str]` | The `error.code` field from the API response. `None` for SMW-style errors that omit `code`. |
| `info` | `str` | The `error.info` field — the human-readable error message. |
| `kwargs` | `Optional[Any]` | The full raw error dict from the response. |

**Example:** When `assertuserfailed` is returned by the API, `APIError` is raised with `code='assertuserfailed'` and `info='Assertion that the user is logged in failed'`. See [test/test_client.py L327-L344](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L327-L344)

**SMW special case:** Semantic MediaWiki errors may omit the `code` field entirely. In this case `code` is `None` and `info` carries the query error text. See [test/test_client.py L346-L361](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L346-L361)

### MediaWikiVersionError

[mwclient/errors.py L12-L14](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L12-L14)

Raised during site initialization when the MediaWiki generator string cannot be parsed, or when the detected version is below the minimum supported (1.16). Raised from `Site.version_tuple_from_generator()` in `client.py`.

### APIDisabledError

[mwclient/errors.py L17-L19](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L17-L19)

Raised by `site_init()` when the API response body is a plain-text string like `"MediaWiki API is not enabled for this site."` rather than valid JSON. See [test/test_client.py L257-L263](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L257-L263)

### MaximumRetriesExceeded

[mwclient/errors.py L22-L24](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L22-L24)

Raised by `Sleeper.sleep()` in `sleep.py` when the retry count exceeds `max_retries`. This surfaces in two places:

* **Transport level** — inside `raw_call()` when 5xx or database lag retries are exhausted.
* **Application level** — inside `handle_api_result()` when `DBConnectionError` retries are exhausted.

See [test/test_client.py L498-L515](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L498-L515)

 and [test/test_sleep.py L49-L54](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_sleep.py#L49-L54)

[mwclient/errors.py L42-L45](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L42-L45)

### UserBlocked

[mwclient/errors.py L48-L50](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L48-L50)

A subclass of `InsufficientPermission`. Raised when an action is attempted while the user account is blocked on the wiki.

### EditError

[mwclient/errors.py L53-L55](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L53-L55)

Base class for errors that occur during page editing operations. Catching `EditError` will also catch `ProtectedPageError` and `FileExists`. Used directly when an edit result returns a `captcha` field (unresolvable CAPTCHA challenge). See [test/test_page.py L192-L215](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_page.py#L192-L215)

### ProtectedPageError

[mwclient/errors.py L58-L80](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L58-L80)

Raised by `page.handle_edit_error()` when an edit attempt returns API error codes such as `protectedpage`, `protectednamespace`, or `customcssskinprotected`.

**Multiple inheritance:** `ProtectedPageError` inherits from *both* `EditError` and `InsufficientPermission`. This means it can be caught by either parent class, which is intentional: a protected-page failure is simultaneously an edit failure and a permission failure.

```
ProtectedPageError
├── EditError      (mwclient/errors.py:53)
└── InsufficientPermission  (mwclient/errors.py:42)
```

**Attributes:**

| Attribute | Type | Description |
| --- | --- | --- |
| `page` | `mwclient.page.Page` | The page object on which the edit was attempted. |
| `code` | `Optional[str]` | API error code string (e.g., `'protectedpage'`). |
| `info` | `Optional[str]` | API error info string. Used as `__str__` output when set. |

`__str__` returns `self.info` if present, otherwise the generic message `'You do not have the "edit" right.'`. See [test/test_page.py L449-L459](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_page.py#L449-L459)

### FileExists

[mwclient/errors.py L83-L100](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L83-L100)

A subclass of `EditError`. Raised by `site.upload()` when the API warns that a file already exists and `ignore=False`.

**Attribute:** `file_name` — the name of the conflicting file.

`__str__` produces: `'The file "X" already exists. Set ignore=True to overwrite it.'`

See [test/test_client.py L882-L907](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L882-L907)

### LoginError

[mwclient/errors.py L103-L125](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L103-L125)

Raised by `site.login()` and `site.clientlogin()` when the login attempt fails (status `FAIL`).

**Attributes:**

| Attribute | Type | Description |
| --- | --- | --- |
| `site` | `mwclient.client.Site` | The `Site` object on which login was attempted. |
| `code` | `Optional[str]` | The result/error code string from the login response. |
| `info` | `str` | The human-readable reason for failure. |

For backwards compatibility, the base `__init__` also stores `{'result': code, 'reason': info}` as the second positional argument to `RuntimeError`.

See [test/test_client.py L628-L664](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L628-L664)

### AssertUserFailedError

[mwclient/errors.py L140-L150](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L140-L150)

Raised by `page.handle_edit_error()` when the API returns `assertuserfailed`. This means an edit was attempted without being logged in while `force_login=True` (the default).

The error message explains the situation and suggests setting `force_login=False` on the `Site` object if anonymous editing is intentional. See [test/test_page.py L440-L447](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_page.py#L440-L447)

### EmailError / NoSpecifiedEmail

[mwclient/errors.py L153-L160](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L153-L160)

`EmailError` is the base class for email-related failures. `NoSpecifiedEmail` is raised when attempting to email a user who has not set up an email address on their account.

---

### InvalidResponse

[mwclient/errors.py L163-L180](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L163-L180)

Raised by `raw_api()` in `client.py` when the server returns a response body that cannot be decoded as JSON. The raw text is stored in `response_text` for diagnostic purposes.

**Common cause:** Using the wrong hostname or path, or hitting a server that is redirecting to a login page.

---

### InvalidPageTitle

[mwclient/errors.py L183-L185](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L183-L185)

Raised by `Page.__init__()` in `page.py` when the API returns an `"invalid"` key in the page info, indicating the requested title contains illegal characters. See [test/test_page.py L61-L78](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_page.py#L61-L78)

## The TYPE_CHECKING Import Pattern

[mwclient/errors.py L1-L6](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L1-L6)

`errors.py` is imported by nearly every other module in the package. If it imported `mwclient.page` or `mwclient.client` at runtime, a circular import cycle would result:

```
client.py → errors.py → client.py  (cycle)
page.py   → errors.py → page.py    (cycle)
```

To provide accurate type annotations on exception attributes (e.g., `ProtectedPageError.page: mwclient.page.Page` and `LoginError.site: mwclient.client.Site`) without triggering runtime imports, `errors.py` uses the standard `TYPE_CHECKING` guard:

```

```

The `if TYPE_CHECKING:` block is only executed by static analysis tools (mypy, Pyright) and IDEs — never at runtime. The type annotations that reference these imports use string literals (forward references) in the function signatures:

* `ProtectedPageError.__init__(self, page: 'mwclient.page.Page', ...)` — [mwclient/errors.py L67-L75](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L67-L75)
* `LoginError.__init__(self, site: 'mwclient.client.Site', ...)` — [mwclient/errors.py L113-L122](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/errors.py#L113-L122)

This keeps the module importable from anywhere while still providing full type information to static checkers.

## Catching Errors: Common Patterns

The table below summarises the most frequent error types a library user needs to handle:

| Scenario | Exception to catch | Key attributes |
| --- | --- | --- |
| Edit on a protected page | `ProtectedPageError` | `.page`, `.code`, `.info` |
| Not logged in when editing | `AssertUserFailedError` | message in `.args[0]` |
| Any edit failure | `EditError` | catches `ProtectedPageError` and `FileExists` too |
| Any permission failure | `InsufficientPermission` | catches `UserBlocked` and `ProtectedPageError` too |
| Upload of duplicate file | `FileExists` | `.file_name` |
| Wrong credentials | `LoginError` | `.code`, `.info` |
| API returns error JSON | `APIError` | `.code`, `.info` |
| Server returned non-JSON | `InvalidResponse` | `.response_text` |
| Retries exhausted | `MaximumRetriesExceeded` | — |
| API is disabled | `APIDisabledError` | — |
| MediaWiki too old | `MediaWikiVersionError` | — |
| Invalid page title | `InvalidPageTitle` | — |
