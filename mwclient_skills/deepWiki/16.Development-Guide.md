## Project Dependencies

The runtime dependencies and optional groups are declared in [pyproject.toml L27-L44](https://github.com/mwclient/mwclient/blob/47ea5b29/pyproject.toml#L27-L44)

:

| Group | Packages |
| --- | --- |
| Runtime | `requests`, `requests-oauthlib` |
| `testing` | `pytest`, `pytest-cov`, `responses>=0.3.0` (not `0.6.0`) |
| `docs` | `sphinx`, `sphinx-rtd-theme` |

## Code Conventions

### Docstrings

The project uses **Google-style** docstrings, processed by Sphinx with the `napoleon` extension. The expected format is:

```

```

Useful Sphinx-specific directives you can embed in docstrings:

| Directive | Purpose |
| --- | --- |
| `.. warning::` | Highlight potential issues |
| `.. note::` | Provide supplementary information |
| `.. seealso::` | Link to related documentation |
| `.. deprecated::` | Mark a function or parameter as deprecated |

Sources: [docs/source/development/index.rst L129-L156](https://github.com/mwclient/mwclient/blob/47ea5b29/docs/source/development/index.rst#L129-L156)

### Type Annotations

The project is fully type-annotated and checked with `mypy` in strict mode. The `mypy` configuration lives in [pyproject.toml L79-L92](https://github.com/mwclient/mwclient/blob/47ea5b29/pyproject.toml#L79-L92)

 The `test.*` module relaxes `disallow_untyped_calls` and `disallow_untyped_defs`.

One notable pattern: `mwclient/errors.py` imports `Page` and `Site` under `TYPE_CHECKING` only to avoid circular imports at runtime. See [Error Handling](/mwclient/mwclient/6-error-handling) for details.

Sources: [pyproject.toml L79-L92](https://github.com/mwclient/mwclient/blob/47ea5b29/pyproject.toml#L79-L92)

### Linting

A `flake` tox environment runs `flake8` against the package source. The `.flake8` configuration file controls the rules applied. This environment is excluded from the sdist build ([pyproject.toml L59-L64](https://github.com/mwclient/mwclient/blob/47ea5b29/pyproject.toml#L59-L64)

).

```

```

Key points:

* Run tests locally before committing (see [Testing](/mwclient/mwclient/7.1-testing)).
* Rebase on `master` if your branch has diverged significantly: `git rebase master`.
* There is no required commit message format, but messages should clearly describe the change.
* GitHub Actions runs the full `tox` matrix automatically on every pull request.
