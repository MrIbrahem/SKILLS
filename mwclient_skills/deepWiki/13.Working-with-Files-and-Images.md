## Purpose and Scope

This page covers the `Image` class in [mwclient/image.py](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/image.py)

 and the `Site.upload()` method in [mwclient/client.py](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py)

 Together they handle reading file metadata, querying file history and usage, downloading file content, and uploading new files to a wiki.

For general page operations that also apply to file pages (reading wikitext, editing, moving, deleting), see [Working with Pages](/mwclient/mwclient/3-working-with-pages). For details on the iteration and pagination infrastructure used by `imagehistory()`, `imageusage()`, and `duplicatefiles()`, see [Iteration and Pagination](/mwclient/mwclient/5-iteration-and-pagination). For error types raised by these operations, see [Error Handling](/mwclient/mwclient/6-error-handling).

### Token Acquisition

Before the upload POST is sent, `upload()` calls `self.get_token('csrf')` to obtain a CSRF token. This token is cached in `self.tokens` [mwclient/client.py L169](https://github.com/mwclient/mwclient/blob/47ea5b29/mwclient/client.py#L169-L169)

 and reused on subsequent calls.

## Error Handling

| Error | Module | When raised |
| --- | --- | --- |
| `errors.InsufficientPermission` | `mwclient/errors.py` | Caller lacks the `upload` right |
| `errors.FileExists` | `mwclient/errors.py` | File already exists and `ignore=False` |
| `errors.APIError` | `mwclient/errors.py` | General API-level failure during upload |

The `upload()` method checks the user's rights against the required `upload` permission before attempting the upload. If the right is absent, `InsufficientPermission` is raised without making an upload API call.

When a file already exists and `ignore=False`, the API returns a warning with key `'exists'`. The client raises `FileExists`. Passing `ignore=True` suppresses this check.
