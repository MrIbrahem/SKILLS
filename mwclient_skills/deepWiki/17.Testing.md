This page covers the mwclient test suite: how it is structured, how unit tests mock HTTP, how integration tests spin up real MediaWiki instances, and how to run each environment locally. For information about the CI pipelines that run these tests automatically, see [CI/CD Workflows](/mwclient/mwclient/7.2-cicd-workflows).

---

## Test Suite Overview

The test suite lives entirely under the `test/` directory and is run via [tox](https://tox.wiki). It has two distinct test modes:

| Mode | Location | Requires network / container? | Run by default? |
| --- | --- | --- | --- |
| Unit tests | `test/test_*.py` | No | Yes |
| Integration tests | `test/integration.py` | Yes (Docker or Podman) | No |

Additional static analysis environments (`flake`, `mypy`) are also managed through tox.

Key points from `tox.ini`:

* All unit test environments install the package with the `testing` extras (`extras = testing`) and run `pytest -v --cov mwclient test`.
* The `flake` environment installs only `flake8` and runs it against the `mwclient` package source.
* The `mypy` environment installs `mypy`, `pytest`, `responses`, `types-requests`, and `types-setuptools`.
* The `integration` environment installs only `pytest` and runs `test/integration.py` directly.
* In CI (via `[gh-actions]`), Python 3.14 maps to `py314`, `flake`, `integration`, and `mypy` all at once.

### Mocking HTTP with responses

Unit tests never connect to a real wiki. All HTTP is intercepted using the [`responses`](https://github.com/mwclient/mwclient/blob/47ea5b29/`responses`)

 library, which registers mock URL patterns and returns pre-configured payloads.

The base `TestCase` class in `test_client.py` provides helper methods that all HTTP-touching tests inherit:

| Helper method | Purpose |
| --- | --- |
| `metaResponse(version, rights)` | Returns a dict shaped like a real `action=query&meta=siteinfo\|userinfo` API response |
| `metaResponseAsJson(**kwargs)` | Same as above but JSON-encoded as a string |
| `httpShouldReturn(body, callback, ...)` | Registers a URL pattern with `responses.add()` or `responses.add_callback()` |
| `stdSetup()` | Registers the meta response, constructs a `mwclient.Site`, then resets the registry |
| `makePageResponse(title, **kwargs)` | Returns a JSON-encoded fake `query.pages` response |

Sources: [test/test_client.py L25-L118](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L25-L118)

**Pattern: `@responses.activate` decorator**

Tests that make HTTP calls are decorated with `@responses.activate`. This activates the interceptor for the duration of the test function. Any call to a URL not registered in that test raises a `ConnectionError`.

```python
@responses.activate
def test_https_as_default(self):
    self.httpShouldReturn(self.metaResponseAsJson(), scheme='https')
    site = mwclient.Site('test.wikipedia.org')
    assert len(responses.calls) == 1
```

Sources: [test/test_client.py L140-L149](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L140-L149)

**Pattern: `mock.patch` for lower-level isolation**

Some test classes bypass HTTP entirely by patching `Site.raw_call`, `Site.raw_api`, or `Site.api` directly. This is used when testing logic that lives above the HTTP layer:

| Class | What is patched | Why |
| --- | --- | --- |
| `TestLogin` | `Site.site_init`, `Site.raw_api` | Test the login flow call sequence without any HTTP |
| `TestClientUploadArgs` | `Site.raw_call` | Control the exact sequence of responses for the multi-step upload flow |
| `TestClientGetTokens` | `Site.raw_call` | Test token retrieval logic for MW 1.23 vs. MW 1.24+ |
| `TestClientPatrol` | `Site.raw_call`, `Site.get_token` | Verify patrol token acquisition and POST |
| `TestClientApiMethods` | `Site.api` | Test `site.revisions()` argument passing |
| `TestPage`, `TestPageApiArgs` | `mwclient.client.Site` (whole class) | Provide a `mock_site` to `Page.__init__` |
| `TestList` | `mwclient.client.Site` (whole class) | Provide a `mock_site` to `List.__init__` |

Sources: [test/test_client.py L529-L710](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_client.py#L529-L710)

 [test/test_page.py L19-L350](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_page.py#L19-L350)

 [test/test_listing.py L107-L465](https://github.com/mwclient/mwclient/blob/47ea5b29/test/test_listing.py#L107-L465)

**Pattern: Retry testing with `mock.patch("time.sleep")`**

Tests that exercise retry behavior patch `time.sleep` to prevent actual delays and count calls to verify the expected number of retries occurred:

```python
@mock.patch("time.sleep")
@responses.activate
def test_api_http_error(self, timesleep):
    ...
    assert timesleep.call_count == 25
```

The count of 25 corresponds to the default `max_retries` value used by the `Sleepers` class.

### Overview

### Container Fixture

The `site` pytest fixture (scope: `class`) is parametrized to spin up three MediaWiki containers in parallel, one per MediaWiki release channel:

| Parameter | Port | Tag |
| --- | --- | --- |
| `latest` | 5002 | `docker.io/library/mediawiki:latest` |
| `legacy` | 5003 | `docker.io/library/mediawiki:legacy` |
| `lts` | 5004 | `docker.io/library/mediawiki:lts` |

Each test class therefore runs three times — once per container. The fixture yields a `mwclient.Site` instance connected to the container and tears down the container when the class is done.

## Running Tests Locally

### Install dependencies

```
pip install -e '.[testing]'
```

The `testing` extras install `pytest`, `pytest-cov`, and `responses`. This is equivalent to what tox installs for the `[testenv]` environment.

Sources: [tox.ini L17-L19](https://github.com/mwclient/mwclient/blob/47ea5b29/tox.ini#L17-L19)

 [docs/source/development/index.rst L62-L65](https://github.com/mwclient/mwclient/blob/47ea5b29/docs/source/development/index.rst#L62-L65)

### Run all unit tests with tox

```
pip install tox
tox
```

### Run a single Python environment

```
tox -e py39
```

### Run unit tests directly with pytest

```
pytest -v --cov mwclient test
```

### Run linting (flake8)

```
tox -e flake
```

### Run type checking (mypy)

```
tox -e mypy
```

### Run integration tests

Requires Docker or Podman installed and running.

```
tox -e integration
```

Or directly with pytest:

```
pytest test/integration.py
```

Note: The first run downloads the three MediaWiki container images (`latest`, `legacy`, `lts`) from Docker Hub, which is approximately 3 GB of network transfer.

Sources: [docs/source/development/index.rst L38-L82](https://github.com/mwclient/mwclient/blob/47ea5b29/docs/source/development/index.rst#L38-L82)
